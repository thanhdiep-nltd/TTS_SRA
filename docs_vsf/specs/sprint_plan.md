# Kế hoạch Sprint Chi tiết
## Dự án: Hệ Thống Cảnh Báo Sớm Học Sinh Có Nguy Cơ Sư Phạm (VSF Student Risk Alert - VSF SRA)

Dưới đây là kế hoạch chi tiết chia làm 7 Sprint dựa trên lịch trình từ mentor và chế độ làm việc thực tế (Thứ Bảy cách tuần).

---

| Sprint / Tuần | Ngày (dự kiến) | Mục tiêu | Công việc thực tập sinh (làm chính) | Mentor hỗ trợ (thông tin, không data) | Trạng thái | Deliverable / Milestone |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Sprint 1**<br>*(Tuần 0)* | 16/07 - 18/07/2026<br>*(Làm Thứ Bảy 18/07)* | Onboarding, thống nhất phạm vi dự án, thiết kế kiến trúc tổng thể và thiết lập môi trường phát triển. | - Đọc lại và đánh giá kiến trúc dự án 'Dự án VinUni' đã làm trước đây để tái sử dụng những gì phù hợp.<br>- Đề xuất kiến trúc hệ thống mới (4 module: Text-to-Query, Multi-Agent, RAG+LLM, OCR)<br>- Viết tài liệu đặc tả yêu cầu rút gọn (mini-SRS) và kế hoạch sprint chi tiết cho 5 tuần còn lại. | - Cung cấp bối cảnh nghiệp vụ: Ban Giám hiệu cần loại báo cáo/KPI gì, quy trình ra quyết định hiện tại.<br>- Giới thiệu stakeholder liên quan (nếu có) và kỳ vọng về sản phẩm.<br>- Review và góp ý kiến trúc, mini-SRS do thực tập sinh đề xuất. | Đang làm | **Tài liệu mini-SRS + kiến trúc hệ thống + kế hoạch sprint 5 tuần được mentor duyệt.** |
| **Sprint 2**<br>*(Tuần 1)* | 20/07 - 24/07/2026<br>*(Thứ Bảy 25/07 nghỉ)* | Chuẩn bị môi trường, xin yêu cầu truy cập | - Thiết kế schema dữ liệu điểm số/môn học ở dạng mock (chưa có dữ liệu thật). *Thiết kế ERD linh hoạt hỗ trợ nhiều trường học khác nhau với nhiều chuẩn điểm khác nhau (hệ 10, hệ 6, hệ chữ A, B, C, D...).*<br>- Setup repo, CI cơ bản, Docker/dev environment, chọn LLM provider, embedding model, framework multi-agent. | - Cung cấp tài liệu quy chế đánh giá học tập mẫu (không kèm dữ liệu học sinh thật). | Chưa bắt đầu | **Thực tập sinh trình bày được ERD (Entity–Relationship Diagram) của các dữ liệu liên quan**<br>**Setup xong về môi trường, dữ liệu giả.** |
| **Sprint 3**<br>*(Tuần 2)* | 27/07 - 31/07/2026<br>*(Làm Thứ Bảy 01/08)* | Xây dựng module Text-to-Query (chuyển câu hỏi tự nhiên thành truy vấn dữ liệu học tập). | - Xây dựng pipeline NL -> SQL/Query bằng LLM, xử lý câu hỏi tiếng Việt về kết quả học tập (hỗ trợ nhiều thang điểm khác nhau).<br>- Kết nối module với schema dữ liệu mock, sinh dữ liệu giả lập (synthetic) để test.<br>- Xây API endpoint cho module, viết unit test và bộ test-case câu hỏi mẫu.<br>- Đánh giá độ chính xác, xử lý trường hợp câu hỏi mơ hồ/sai schema. | - Cung cấp bộ câu hỏi mẫu BGH thường hỏi (vd: điểm trung bình khối 10 học kỳ 1).<br>- Cung cấp tiêu chí đánh giá độ chính xác/định dạng câu trả lời mong muốn.<br>- Review code, phản hồi qua các buổi sync đầu/cuối tuần. | Chưa bắt đầu | **Demo module Text-to-Query chạy được trên dữ liệu mock + tài liệu API.** |
| **Sprint 4**<br>*(Tuần 3)* | 03/08 - 07/08/2026<br>*(Thứ Bảy 08/08 nghỉ)* | Phân tích các yếu tố tác động đến kết quả học tập của học sinh | - Liệt kê được các yếu tố tác động, mức độ tác động (mạnh hay nhẹ, tích cực hay tiêu cực, rõ ràng hay mơ hồ). Ví dụ:<br>  - Điểm số (nhiều chuẩn điểm).<br>  - Mức độ hoàn thành bài tập về nhà, quá trình tự học thông qua LMS.<br>  - Các khảo sát độ hài lòng của học sinh.<br>  - Các hành vi (Quậy phá, Trầm Cảm, ...) hoặc các trường hợp chăm sóc đặc biệt (trầm cảm, bệnh lý mãn tính,…)<br>  - Chuyên cần.<br>  - Biến cố gia đình.<br>- *Cài đặt các thuật toán phân tích học thuật chuyên sâu:* Mô hình dự báo nguy cơ học thuật trước thi ($P(Fail)$), Phân cụm năng lực ẩn NMF. | - Cung cấp schema về các dữ liệu liên quan.<br>- Tư vấn về trọng số, loại bỏ nhiễu, cách hiển thị khi có kết quả dự báo.<br>- Review kết quả đánh giá. | Chưa bắt đầu | **Trình bày được các yếu tố tác động và tầm ảnh hưởng của từng yếu tố.**<br>**Chạy thử mô hình nếu hoàn thành sớm.** |
| **Sprint 5**<br>*(Tuần 4)* | 10/08 - 14/08/2026<br>*(Làm Thứ Bảy 15/08)* | Xây dựng module Multi-Agent cho báo cáo tự động và dự báo kết quả học tập. | - Thiết kế kiến trúc multi-agent: agent thu thập dữ liệu, agent phân tích xu hướng, agent sinh báo cáo, agent dự báo.<br>- Tích hợp với module Text-to-Query của tuần 2.<br>- Xây dựng report generator (biểu đồ trực quan, tóm tắt tự động).<br>- Xây dựng mô hình dự báo học lực cơ bản (trend/regression hoặc LLM-based forecasting) hỗ trợ các hệ điểm đa dạng. | - Cung cấp mẫu báo cáo BGH mong muốn (bố cục, nội dung, tần suất báo cáo theo kỳ/năm).<br>- Cung cấp tiêu chí/giả định cho phần dự báo (theo học kỳ, theo khối lớp...).<br>- Review logic nghiệp vụ của các agent và tính hợp lý của báo cáo/dự báo sinh ra. | Chưa bắt đầu | **Module báo cáo tự động + dự báo hoạt động demo, tài liệu kiến trúc multi-agent.** |
| **Sprint 6**<br>*(Tuần 5)* | 17/08 - 21/08/2026<br>*(Thứ Bảy 22/08 nghỉ)* | Xây dựng module RAG + LLM phân tích độ khó và độ phù hợp của đề thi so với giáo trình. | - Xây dựng pipeline RAG: ingest giáo trình/đề cương mẫu, chunking, embedding, lưu vector DB.<br>- Kết hợp LLM để đối chiếu đề thi với nội dung giáo trình, đánh giá độ khó/độ phù hợp.<br>- *Tích hợp OCR trong hai pipeline:* Pipeline 1 để xử lý dữ liệu ingest giáo trình/đề cương mẫu (chunking, embedding, vector DB) và Pipeline 2 để OCR bóc tách đề thi kiểm tra do giáo viên tải lên.<br>- Xây API/UI hiển thị kết quả phân tích đề thi.<br>- Viết test-case với vài đề thi mẫu (giả lập hoặc công khai). | - Cung cấp giáo trình/đề cương mẫu (dùng bản mẫu/placeholder, không phải chương trình thật nếu nhạy cảm).<br>- Cung cấp tiêu chí đánh giá độ khó đề thi hiện tại trường đang áp dụng (nếu có).<br>- Review kết quả đánh giá độ khó do hệ thống sinh ra, góp ý điều chỉnh prompt/logic. | Chưa bắt đầu | **Demo tính năng phân tích độ khó đề thi dựa trên RAG + LLM.** |
| **Sprint 7**<br>*(Tuần 6)* | 24/08 - 27/08/2026<br>*(Kết thúc 27/08)* | Kiểm thử toàn diện, hoàn thiện sản phẩm, triển khai và demo bàn giao. | - Test toàn diện: unit test, integration test, UAT với dữ liệu mock/synthetic.<br>- Tối ưu hiệu năng, sửa lỗi, hoàn thiện UI/UX dashboard cho Ban Giám hiệu.<br>- Viết tài liệu hướng dẫn sử dụng + tài liệu kỹ thuật bàn giao.<br>- Chuẩn bị triển khai (Railway/Docker hoặc môi trường công ty chỉ định).<br>- Chuẩn bị và trình bày demo cuối kỳ; tổng kết/rút kinh nghiệm (retro). | - Hỗ trợ kết nối môi trường triển khai thật (không kèm dữ liệu thật của trường).<br>- Review tài liệu bàn giao và kịch bản demo.<br>- Sắp xếp buổi demo với stakeholder/công ty.<br>- Đánh giá kết quả thực tập, góp ý định hướng phát triển tiếp theo cho thực tập sinh. | Chưa bắt đầu | **Hệ thống hoàn chỉnh đã triển khai + tài liệu bàn giao đầy đủ + buổi demo cuối kỳ + đánh giá thực tập.** |
